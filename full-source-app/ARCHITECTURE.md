# Veo Workflow Tools Architecture

## Dependency direction

```text
HTTP/UI -> workflow application -> workflow engine -> node executor
                                               -> integration contract
                                               -> concrete adapter
```

The workflow module must not import Prisma, Electron IPC, captcha transport,
browser automation, cookies, or `Veo3Service` implementations directly.

## Source of truth

Server source lives in `apps/server/src`. The `apps/server/dist` directory is
generated by `npm --prefix apps/server run build` and must not be edited.

## Stable integration boundaries

- `src/integrations/flow/FlowGateway.js`: the only Flow surface used by workflow.
- `src/integrations/captcha/CaptchaGateway.js`: normalized readiness, token and reset API.
- `src/integrations/browser/ElectronBrowserBridge.js`: server-to-Electron transport.
- `src/integrations/profiles/ProfileExecutionSessionProvider.js`: cookies, locale and token refresh.
- `src/integrations/ai/BeeknoeePromptClient.js`: OpenAI-compatible prompt generation and SSE parsing.
- `src/contracts/integration.js`: contracts and integration error shape.

Google endpoint, payload, header, cookie or captcha changes belong behind these
boundaries. They must not change workflow graph scheduling.

## Workflow extension points

- `src/modules/workflow/engine/NodeExecutorRegistry.js`: node registration and versions.
- `src/modules/workflow/nodes`: standalone node executors.
- `src/modules/workflow/versioning/workflowVersioning.js`: backward-compatible node migration.
- `src/modules/workflow/workflow.engine.js`: DAG scheduling, retries and run control only.

To add a node:

1. Add its version to `BUILTIN_NODE_VERSIONS`.
2. Add one executor with `type`, `version` and `execute(context)`.
3. Register the executor in `createBuiltinNodeExecutors`.
4. Add migration logic when the saved node configuration changes.
5. Add an executor test and a workflow fixture.

Generation nodes still using `executeLegacy` are compatibility adapters. Move
them into `src/modules/workflow/nodes` one at a time without changing the DAG
engine or stored workflow format.

## Verification

```powershell
npm --prefix apps/server run typecheck
npm --prefix apps/server run test:architecture
npm --prefix apps/server run build
```

`tests/architecture/dependencyBoundaries.test.js` prevents direct integration
dependencies from leaking back into the workflow engine.
